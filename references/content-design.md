# 内容设计规则

设计顺序：**先术语，后章节**。术语是二级窗口的弹药，章节是让术语自然出现的叙事线。

## 1. 层级与章节

- 总量 12~18 章，分 1~6 层 + 工具层（graph / glossary / quiz 三个 id 固定）。零基础主题建议：
  - 第 1 层 · 认识：它是什么、和近邻概念的区别、注册/准备
  - 第 2 层 · 界面/准备：认识界面、第一个实操
  - 第 3 层 · 低门槛实操：不装环境就能做的操作
  - 第 4 层 · 核心技能：日常主干工作流
  - 第 5 层 · 协作/深入
  - 第 6 层 · 进阶与避坑
- 每章 ≤15 分钟，crumb 里标时长；跟做型章节标「跟着做」。
- 每章结构：`crumb` → `h1` → `lede`（一两句承诺）→ 正文 → `mark-read` → 空 `chapter-nav`（自动填充）。

## 2. 正文写法

- **类比优先**：每个硬概念先给一个生活类比（Git=修订记录，GitHub=云端协作文档），再给定义。
- 步骤用 `.steps` 步骤卡（跟做流程 3~8 步）；对比用 `.cols`（col x 是红色错误示范栏）；并列速览用 `.cards`（data-g 控制色条）。
- `callout` 四色：默认提示 / `ok` 鼓励与「读完你会得到」/ `warn` 注意 / `bad` 危险红线。
- 命令块 `.cmd`：`data-cmd` 属性放**可复制的原文**（含换行，与展示一致）；展示区可用 span 着色（p 提示符、k 参数、s 字符串、c 注释、w 警告）。
- FAQ/避坑章放 `<div id="misList"></div>` 容器即可，条目由 MISCONCEPTIONS 渲染。
- 不要把关键解释写死在正文里——下沉到 CONCEPTS，正文用术语名触发自动链接。

## 3. CONCEPTS 字段规范（核心）

```js
termId:{name:"中文名", en:"English", alias:["别名"], g:"分组key", ch:"章节id",
  short:"一句话短说明（搜索结果用）",
  def:"一句话定义（抽屉高亮框，能独立成立）",
  body:"`<p>2~4 段展开，<b>关键结论</b>加粗</p>`",
  rel:["相关概念id"], src:"在哪里遇到 / 出处"},
```

- 数量 30~40 个。少于 25 抽屉层就单薄了；多于 45 写不过来。
- `def` 标准：读者只看这一句能明白个大概；`body` 补 2~4 个面向（是什么/为什么/怎么用/常见误区）。
- `rel` 3~8 个且**成对书写**（A 的 rel 里有 B，B 里也有 A）；图谱孤岛 = 质量不过关。
- `ch` 必须指向真实章节 id；`g` 必须是 GROUP_NAMES 的 key。
- `name`/`alias` 会被自动链接到正文首次出现处（长词优先，code/pre/summary 内不参与）。常用字词做 name 没问题（如「提交」），但要确认链接目标语义正确；歧义词用 alias 收编。
- GROUP_NAMES 六组语义按主题改写（如编程主题：基础/语法/工具链/协作/生态/职场）。

## 4. 数据区数量基准

| 数组 | 数量 | 要点 |
| --- | --- | --- |
| GLOSSARY | 30~50 | 字段 c/e/u(/n)，分组名与 GROUP_NAMES 呼应 |
| ROUTES | 3~4 | 每条 3~6 步 [标题,说明]，out 一句承诺 |
| MISCONCEPTIONS | 8~12 | t 常见误判句 / bad 错法 / good 做法（可含 code）/ goto |
| QUIZ | 10 | 每题 4 选项，e 解释要讲「为什么」，goto 指向对应章 |

## 5. 欢迎层与文案

- 欢迎层导语三件事：写给谁、一共多少节、虚线词怎么用。
- 四张入口卡指向：全局认知章、最实用的一章、图谱、自测。
- 语言风格：说人话、有态度、动词开头；禁止「本文将介绍」式套话。
